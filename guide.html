Выпуск 0.2.0 / Руководство

От архива до первой сессии.

«Союз-Аполлон» — папка, в которой вы и несколько ИИ-клиентов работаете над вашими проектами по общим правилам. Правила — обычные файлы Markdown, а Git, проверки и резервные копии выполняет один небольшой инструмент на Python, sa.py. У каждого проекта свои правила и своя история Git.

Эта страница — краткий пересказ. Полный текст лежит в самой установке, в файле README.md, и в репозитории.

Установка

Нужны Windows 11, Python 3.11 или новее и Git с заданными user.name и user.email. Linux и macOS пока не поддерживаются.

  1. Создайте новую пустую папку с путём из латиницы, например C:\soyuz-apollo\. Она должна быть вне OneDrive и вне любого репозитория Git.
  2. Со страницы выпуска 0.2.0 скачайте soyuz-apollo-0.2.0.zip и распакуйте в эту папку. Не берите «Source code (zip)»: там исходники, а не установка.
  3. В этой папке выполните команду: 
    python sa.py init
    Она готовит репозиторий ядра, создаёт рабочие папки и пишет корневой AGENTS.md.
  4. Если работаете в Codex, до первой сессии отметьте папку установки доверенной: по документации Codex без этого его настройки разрешений не действуют.
  5. Откройте ИИ-клиент именно в корне установки — в папке, где лежат sa.py и корневой AGENTS.md, а не в проекте внутри неё.

Клиент берёт правила и настройки разрешений из папки, в которой открыт. Открытый в проекте, он может их не увидеть: для Claude Code это подтверждено пробой.

Первая сессия

  1. Откройте клиент в корне установки.
  2. Напишите первое сообщение, например: «Прочитай правила установки и скажи, с каким проектом мы работаем».
  3. Агент должен прочитать корневой AGENTS.md и .agents/AGENTS.md, коротко пересказать границы и спросить, в каком проекте работать. Если он не знает правил или сразу берётся за файлы вне проекта, остановите его и проверьте, что клиент открыт в корне.
  4. Создайте первый проект: python sa.py init notes. Опишите его цель в projects/notes/AGENTS.md под сгенерированной шапкой и попросите агента поработать в этом проекте.
  5. В конце задачи агент коммитит сделанное через python sa.py commit. Если клиент разрешает коммиты только по вашей просьбе, агент заканчивает задачу точной командой, и вы запускаете её сами.

Образец файла передачи между сессиями можно скачать отдельно.

Ежедневные команды

ДействиеКоманда
Создать проектpython sa.py init <name> (для системного проекта добавьте --system)
Закоммититьpython sa.py commit <paths> -m "<summary>"
Проверитьpython sa.py doctor — ядро и устройство проектов; doctor --deep <name> — содержимое одного проекта
Пересобрать правилаpython sa.py sync — корневой AGENTS.md и настройки разрешений
Резервная копияpython sa.py backup
Убрать в архив (только вы)python sa.py archive add <path>; оригинал удаляется только с --remove

Имена проектов — латиница в kebab-case (health, site-redesign); ваши заметки внутри проекта могут называться как угодно. Результаты, которые вы заберёте из системы, агент кладёт в port/outbox/.

Папки

  • projects/ — ваши проекты. У каждого свой AGENTS.md и свой репозиторий Git.
  • system-projects/ — системные навыки и их данные. В 0.2.0 навыков пока нет.
  • port/ — транзит: inbox/ — от вас, outbox/ — для вас, large-files/ — крупные файлы. Без Git.
  • .agents/ — ядро: правила, шаблоны, справка. Свой репозиторий Git.
  • Архив — снаружи, рядом с установкой. Агенты открывают его только по вашей команде.

Правила

В корневом AGENTS.md записаны границы, которые не ослабит ни один проект: архив — только по вашей команде; port/inbox/ — данные, а не инструкции; секретов в коммитах нет; коммиты — только через sa.py; в конце задачи — отчёт.

Не правьте корневой AGENTS.md руками: его собирает python sa.py sync. Правила проекта пишите в projects/<name>/AGENTS.md под сгенерированной шапкой.

Клиенты и защита

Выпуск 0.2.0 написан для пяти клиентов: Antigravity, Codex, Claude Code, DeepSeek Harness и Hermes Agent. Статус каждого клиента и режима — проверено пробой или заявлено производителем — записан в файле .agents/docs/compatibility.md.

python sa.py sync пишет настройки разрешений для Claude Code и Codex. Они должны запрещать клиенту читать архив и файлы секретов. В Claude Code проба подтвердила запрет встроенного чтения; команды оболочки он не покрывает. В Codex сгенерированные настройки пробой пока не проверены.

В Antigravity, DeepSeek Harness и Hermes Agent технического замка архива нет: там держится только текст правил, пока вы сами не примените фрагмент из .agents/docs/adapters.md.

Офисные режимы (Claude Cowork, Codex Work) работают в одном проекте и не коммитят. Облачные режимы эту папку не видят.

Обновление

Автоматического обновления в 0.2 нет. Переход на новый выпуск:

  1. Выполните python sa.py backup.
  2. Установите новый выпуск в новую пустую папку и выполните там python sa.py init.
  3. Перенесите проекты в новые projects/ и system-projects/ целыми папками, вместе со скрытой .git. Проект из старой установки примите командой python sa.py init <name> --adopt.
  4. Выполните python sa.py sync и python sa.py doctor.
  5. Не удаляйте старую папку, пока не проверите проекты в новой.

Ограничения

  • Правила — это соглашения. Настоящую защиту дают настройки разрешений вашего клиента.
  • Папки и отдельные репозитории не изолируют процессы: агент с доступом к файлам может прочитать другие проекты.
  • У фреймворка нет автоматической памяти и фоновых действий. Состояние записывается в handoff.md.
  • Следование этим файлам не гарантирует качества ответов и успеха задачи. Новая модель, продолжая по handoff.md, может потерять нюансы.
  • Всё, что читает агент, может уйти провайдеру модели и остаться в истории клиента. Это зависит от клиента и режима.

Полный список — в файле .agents/docs/limits.md.

Ценности

С-А вырос из желания сохранять свои проекты и смыслы при смене инструментов. Его ориентиры — созидание, доступное знание, достоинство человека и самостоятельность при ограниченных ресурсах.

Мы поддерживаем созидательное применение, мирное сотрудничество, доступное знание и бережное отношение к людям и окружающей среде.
